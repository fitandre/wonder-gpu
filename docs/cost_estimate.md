# Token & cost estimate — kayfabe roadmap loop

Generated by `orchestrator/estimate_cost.py` against `orchestrator/task_graph.yaml`
on 2026-09-11, using Vertex AI global-endpoint pricing verified the same day.
**This is a planning estimate, not a bid.** Re-run the script after Phase 0
completes — it's the one phase bounded enough to calibrate the rest against.

## Methodology & assumptions (change these before trusting the number)

- One "call" ≈ one Vertex request within an agentic iteration (propose →
  write → test → fix). Call counts per phase come from the roadmap's own
  complexity signals: phases framed as open-ended reverse-engineering (P1,
  P2, P5) get far more calls than phases that extend an established pattern
  (P0, P3, P7).
- Average tokens per call, by tier:
  | Tier | Avg input/call | Avg output/call | Why |
  |---|---|---|---|
  | Opus 5 | 50,000 | 6,000 | Design/spike work pulls in broad context (multiple files, traces, prior design docs) and spends heavily on reasoning output |
  | Sonnet 5 | 30,000 | 3,000 | Routine implementation against an established pattern — one to a few files of context |
  | Haiku 4.5 | 8,000 | 800 | Chores: log triage, commit messages, status updates, boilerplate |
- **No prompt caching in the baseline table below** (worst case). A second
  table shows the same estimate assuming 40% of input tokens are cache hits
  — realistic once the loop is reusing a stable system prompt + repo
  conventions across many calls in a task, which `vertex_client.py` is
  already built to do.
- GPU test infrastructure (GKE `g2-standard-4`, 1× L4) is priced separately
  at $0.70/hr on-demand and is **not** part of the token cost — it's the
  second half of the grand total.

## Why this number should be treated as a wide band, not a quote

The dominant source of uncertainty is call count, not token size or price
(those are fixed and verified). Call counts for P1, P2, and P5 are
reverse-engineering work with no spec to bound iteration count against —
the roadmap itself flags these as the least predictable phases. A realistic
planning range is **roughly $1,200 – $4,000** for the full P0–P8 run
(tokens + GPU infra), with the low end assuming these phases go about as
smoothly as P0/P3/P7, and the high end assuming they take ~2× the assumed
iterations, which is well within plausible given the nature of the work.

**Recommended approach:** don't fund the whole roadmap up front. Run Phase 0
first — it's bounded, it's mostly extending existing, well-understood code,
and `token_ledger.py` will give you real $/task-cycle numbers from it. Scale
the rest of the estimate from that measurement instead of these assumptions.
